# N주차 과제 제목

## 문제 상황

어떤 기능을 구현하는지, 무엇이 잘못될 수 있는지 이해할 배경을 적습니다. 해답은 적지 않습니다.

## 입력과 동작 조건

입력 형식·길이·범위·바이트 순서, 출력 조건, 성공과 실패의 의미, 보존할 상태를 명시합니다. 데이터 수치와 조건이 서로 충돌하지 않는지 확인합니다.

## 실행 환경과 가정

언어, 타깃, 타입 크기, 동시 접근 여부 등 풀이에 필요한 전제를 적습니다. 실제 보드가 없어도 검토할 수 있는 범위를 구분합니다.

## 검토할 원본 코드

`starter/`에 개선 전 함수를 추가하고 여기에 링크합니다. 의도된 결함이 남아 있어야 합니다. 완성된 정답을 복사하지 않습니다.

## 구현 과제

발견한 모든 근본 원인, 수정 코드, 인터페이스 선택과 단점, 검증 결과를 요구합니다. 바꿀 수 있는 인터페이스와 반드시 유지할 계약을 구분합니다.

## 검증할 입력

정상·경계·오류 사례와 기대 동작을 적습니다. 필요하면 `cases.csv`를 추가합니다. 실제 실행값과 예상값을 구분합니다.

## PR 제출물

`submissions/weekNN/<github-id>/`에 개선 코드, 테스트, 설명과 실제 실행 결과를 추가합니다. `weeks` 원본은 변경하지 않습니다.
