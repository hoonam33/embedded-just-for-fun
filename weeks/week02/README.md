# 2주차 와이퍼 센서값 변환

주제는 자료형과 배열, 메모리와 포인터입니다. 32-bit MCU의 C 코드에서 센서값을 변환하는 함수를 검토하고 구현을 완성하세요.

## 문제 상황

비가 내리기 시작해 자동차 앞유리에 물이 맺혔습니다. MCU가 빗물 센서값을 읽어 와이퍼를 켜거나 끄도록 아래 변환 함수의 초안을 검토합니다.

## 센서 입력과 동작 조건

1. 센서는 **부호 없는 16비트 정수**를 **2바이트**로 보냅니다.
2. 낮은 바이트가 먼저 오는 **little-endian** 방식입니다.
3. 유효한 빗물 양은 **0~1000**이며 양 끝을 포함합니다.
4. 정상 변환값이 **500 이상이면 ON**, **500 미만이면 OFF** 명령을 만듭니다.
5. **NULL 입력**, **길이가 정확히 2가 아닌 입력**, **1000을 넘는 변환값**은 실패입니다. 실패한 입력에서는 **새 와이퍼 명령을 만들지 않습니다**.
6. 호출자는 입력 배열과 실제 읽을 수 있는 길이를 제공합니다. 함수는 호출 중에만 입력을 읽고, **입력 원본을 바꾸거나 입력 주소를 보관하지 않습니다**.

실패를 정상 측정값 0이나 OFF 명령으로 처리하지 마세요. 이 문제는 변환과 명령 생성의 계약을 다루며, 실제 차량의 통신·센서 드라이버·안전 제어 정책을 구현하는 과제가 아닙니다.

## 타깃의 자료형 조건

| 항목 | 크기 또는 조건 |
| --- | --- |
| 1바이트 | 8비트 |
| `char` | 부호 있음 |
| `int` | 4바이트 |
| 데이터 포인터 | 4바이트 |
| `uint8_t` | 1바이트 |
| `uint16_t` | 2바이트 |
| `uint32_t` | 4바이트 |

위 조건은 이 과제의 타깃에 대한 정보입니다. “32-bit MCU이므로 모든 자료형이 4바이트”라고 가정하지 마세요. 호스트 PC에서 시험한다면 실제 타입 크기와 컴파일러 옵션을 기록해 타깃과의 차이를 구분하세요.

## 검토할 원본 코드

[starter/decode_rain.c](starter/decode_rain.c)에 개선 전 코드를 그대로 보존했습니다.

```c
int *decode_rain(const char bytes[]) {
    int rain = bytes[0] | (bytes[1] << 8);
    return &rain;
}
```

이 함수는 결함을 찾기 위한 초안이며 완성된 실행 프로그램이 아닙니다. `main`이나 호출 코드는 포함하지 않습니다. 먼저 코드와 계약을 검토하고, 개선한 코드에 자신의 테스트를 붙이세요.

## 구현 과제

초안의 **모든 근본 원인**을 찾아 수정하세요. 함수의 매개변수와 반환형은 바꿀 수 있습니다. 특정 인터페이스로 답을 맞추는 문제가 아닙니다.

- 원시 바이트의 자료형, 부호와 크기를 어떻게 표현할지 정합니다.
- 배열을 읽을 수 있는 조건과 입력 검사의 순서를 정합니다.
- 변환 결과의 저장 공간, 수명, 값과 포인터의 사용 방식을 정합니다.
- 성공과 실패를 알리는 규칙, 결과를 사용할 수 있는 시점, 호출자의 명령 생성 규칙을 정합니다.
- 정상 입력·경계 입력·오류 입력으로 자신의 구현을 검증합니다.

선택한 설계의 근거와 감수한 단점도 설명하세요. 문제에서 보장한 조건 안의 오류와 실제 환경에서 추가로 검토할 사항을 구분합니다. 코드의 일부만 고쳐 현재 입력에서 우연히 동작하는 것으로 끝내지 마세요.

## 검증할 입력

[cases.csv](cases.csv)에 요구 조건으로 계산한 예상 결과를 정리했습니다. **실제로 실행한 결과가 아니며 정답 구현도 아닙니다.** 자신의 코드로 실행한 결과를 별도로 제출하세요.

최소한 다음을 포함합니다.

- 정상값 0, 128, 255 및 명령 경계 499와 500
- 유효 범위 경계 1000과 1001
- 높은 바이트의 상위 비트가 켜진 입력과 최대 16비트 값
- NULL, 길이 0·1·3
- 입력 원본이 변경되지 않는지
- 실패 시 새 명령이 생성·전송되지 않는지
- 자신의 결과 전달 방식에서 출력이 언제 유효하고, 실패 전후에 어떻게 되는지

테스트는 실제로 유효한 배열과 그에 맞는 길이를 제공해야 합니다. 짧은 배열에 거짓 길이를 붙이거나 임의 주소를 만들어 검증 함수가 안전하게 탐지해 줄 것이라고 가정하지 마세요. 길이 1 검사는 실제 한 바이트 배열로도 확인합니다.

`cases.csv`의 `empty_input`은 C에서 0길이 배열을 선언하라는 뜻이 아닙니다. 유효한 버퍼 주소에 처리할 길이 0을 전달하고, 배열 원소를 읽지 않은 채 실패하는지 확인합니다.

정상 입력을 받으면 현재 상태가 이미 같더라도 해당 ON/OFF 명령을 만들 수 있어야 합니다. 상태 변화 여부와 새 명령 생성 여부는 별개입니다. 원문은 실패 시 내부 출력 객체의 변경 여부까지 고정하지 않으므로, 본인이 정한 계약과 호출자 사용법을 일관되게 설명하세요.
